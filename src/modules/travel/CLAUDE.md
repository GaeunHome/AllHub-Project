# 旅遊（travel）的注意事項

全站的規則在根目錄的 `CLAUDE.md` 與 `.claude/rules/`（讀寫相關的檔案時自動載入），這裡只寫這個部分自己的。

- 使用者的痛點：用 Excel 排行程，中途改很麻煩、還要自己查。所以時間不用手填：`lib/schedule.ts` 的 `scheduleDay()` 照順序、停留與交通的分鐘數算出每一項的時間（一天從 9 點開始，第一項的固定時間就是這一天的開始；中間的固定時間早到就等、來不及標「晚 N 分鐘」），資料庫不存時間，拖曳換順序整天自動重排。
- 頁面：`/travel` 清單、`/travel/<id>` 行程（想去的點加每天一欄的看板，下面是平常收起來的同行的人與出發前清單，標題列寫幾人、還有幾項）、`/travel/join/<id>/<token>` 加入（打開不會自動加入，要按按鈕）。項目的 `day` 是 null 時在想去的點。首頁卡片是今天的行程（使用者要的：今天有排項目才出現，`web/pages/home-card.tsx` 的 `travelCardShown()`，想去的點與別天的不算，還沒出發也不顯示）。
- 同行的人都要有 AllHub 帳號（使用者的決定）：群組連結不存資料庫，`service/join-link.ts` 用 `SESSION_SECRET` 衍生的金鑰對旅程 id 與 `join_generation` 算 HMAC，建立者隨時可以再複製；撤銷時 generation 加一，舊連結失效，已經加入的人不受影響。沒登入的人點連結：`proxy.ts` 只替 `/travel/join/` 帶 `?next=`，登入後用 `messages.ts` 的 `safeNextPath()` 回去（只收站內路徑）。沒有旅遊權限的人照舊回首頁，要站長先開。
- 一起編輯是輪流存檔，不是同時打字：Vercel 沒有常駐連線，也不加輪詢（使用者不要多的流量）。項目修改比對 `version`，別人先改過就請他重新看過；拖曳傳「放到哪一項前面」不傳位置編號，兩個人同時拖也不會互相蓋掉，要放在前面的那一項不在了就放最後（`service/items.ts` 的 `moveItem()` 與 `web/board-model.ts` 的 `moveInBoard()` 算法一樣，畫面先換好再等伺服器）。其他人靠站內通知知道（`service/notices.ts`，同一人同一趟十分鐘一則）與切回分頁時重新讀（`trip-refresh.tsx`）。
- 看板的版面（使用者選的，`web/travel.css`）：每一項一張薄卡，左邊一欄到與離開的時間，右邊名稱、最多兩行的備註與工具列（查地圖、留言都是小圖示，圖示 28px、點擊範圍撐到 44px，留言數寫在圖示旁），交通時間在兩項之間是一整行的連結，整天路線是圖示。
- 手機一次看一天（使用者選的，`web/components/day-tabs.tsx`）：看板本身還是橫向的（每欄整頁寬、`scroll-snap`，想去的點用 `order` 排最後），上面多一排貼在導覽列下的切換列，手指滑與按切換列都能換天，切換列照 `IntersectionObserver` 跟著；拖到別天照舊靠邊緣自動捲，所以不用另外做一套。打開時先看今天，不在旅途中是第 1 天（`board-model.ts` 的 `startDay()`，手機的時鐘），`useStartDay()` 只跑一次，存檔後重讀不會把人拉回去，要在看板的外層呼叫，同層的 layout effect 跑的時候 ref 還沒接上。`.trv-board` 要 `relative`：畫面外的欄裡有 `sr-only`，不然絕對定位會逃出捲動區，把整頁撐寬。
- 拖曳是自己寫的（使用者同意：比套件好就留著，不要造成問題；有真機問題再換 dnd-kit，影響範圍只有 `web/components/use-board-drag.ts` 與 `trip-board.tsx`）：pointer 事件，滑鼠與手指共用，只有把手能拖（`touch-action: none`，手機 44px），其他地方照樣能捲動頁面。
  - 落點看左右位置（`dropAt()`）：空的那一天比較矮，手指低於它也算放進去；放在標題或空白處也算數，經過欄位間的空隙沿用上一個落點，移出看板是取消。
  - 手指停在邊緣不動也會繼續捲（`requestAnimationFrame`），拖曳時關掉看板的捲動吸附（`[data-dragging]`），不然兩邊打架。
  - 位置不存 state，每動一下重畫整個看板手機會卡，落點變了才重畫。
  - 放回原位不送出（`isSamePlace()`，service 也回 false），不失效快取也不通知。順序不是內容，拖曳不動 `version`，別人正在改這一項時不會被說成衝突。
  - 把手可以用方向鍵：上下換順序、左右換天，焦點跟著卡片走（跨天時卡片重新掛載，`TripBoard` 的 layout effect 放回去），結果念在 `role="status"`。Esc 取消，⋮ 裡也有上移、下移、移到別天。
- 當天模式（使用者選的：旅程頁頂端一張卡片，`web/components/today-card.tsx`、`web/today-view.ts`）：下一站、幾點到、開導航與今天的時間軸。日期與時間一律用手機的時鐘（`deviceClock()`）：伺服器只有台北時間，人在日本會差一小時；伺服器照台北日期判斷今天在旅途中時先留骨架，接手後才不會把看板往下推。`lib/maps.ts` 的 `navigateUrl()` 不帶出發地，Google Maps 才會用手機現在的位置。
- 複製行程文字（`web/trip-text.ts`、`copy-trip-button.tsx`）：⋮ 選單複製整趟，每一天的標題旁複製單日，貼到 LINE 給沒有帳號的親友看。時間、地點加 Google Maps 連結（使用者選的）：沒貼連結的地點用名稱與目的地查，交通與其他不放。想去的點不列，備註不帶出去（可能有訂位代號這類私人內容）。
- 同行的人的名字與頭像讀自 `core_users`，所以 `cachedTrip` 另外標 `core:users`（`service/cache-tags.ts` 的 `usersTag`：快取檔不能 import `@/core/auth`，tag 放在模組自己的 cache-tags 轉一手）。
- 地點：不接付費 API（使用者的決定）。`lib/maps.ts` 只解析貼上的 Google Maps 連結（名稱與座標，只收 Google 的網域）與組出開地圖的網址（查地圖、兩點之間的大眾運輸、整天路線最多 9 個中途點）；`maps.app.goo.gl` 短網址由伺服器用 `externalFetch(redirect: "manual")` 問一次，轉去的網址也要是地圖才採用，問不到就手動填。交通時間由使用者按「查路線」看完填回來。**尚未用真實連結驗證**。不做離線（使用者的決定）。
- 分帳（使用者要的，每筆選貨幣換算台幣；v0.2.11 參考 LINE 的分帳龍寶寶加了不平分、好幾個人付、日期與類別、每個人的帳與明細、記還款與複製結算；`lib/expenses.ts`、`service/expenses.ts`、`web/expense-view.ts`、`web/components/expense-panel.tsx`、`expense-form.tsx`、`repayment-form.tsx`）：一筆帳是項目、金額、貨幣、匯率、日期（`spent_on`）、類別（`category`，使用者選的八類 `EXPENSE_CATEGORIES`：餐飲、交通、住宿、門票、購物、娛樂、伴手禮、其他，舊帳沒有日期與類別，類別算其他）、誰付與怎麼分，都是同行的人才能付或分（修改舊帳時已經離開的人留著），所有成員都能記、改、刪、按已結清與記還款，寫入都經 `inMemberTrip()`。
  - 金額存外幣的分 `amount_cents`，匯率存百萬分之一 `rate_micros`（台幣是 1000000），換算後的台幣不存，用 `twdOf()` 算（BigInt，四捨五入到元），不然改匯率時對不起來。
  - 記帳視窗（使用者選的「分段切換」）：誰付的預設一個人（`paid_by`），切到「好幾個人」時每人填付了多少，加起來要剛好等於這一筆，存在 `travel_expense_payers`（一個人付時沒有列；`paid_by` 寫付最多的人，舊程式讀得懂，那個人刪除帳號時整筆跟著刪）；怎麼分是 `平分｜照金額｜照比例`（`split`，只決定表單怎麼顯示），每個人的 `travel_expense_shares.weight` 平分是 null、照比例是份數（1–99，`MAX_UNITS`）、照金額是外幣的分（加起來要剛好等於這一筆）。照金額與照比例在表單裡各自一組格子，照比例預設每人一份；日期預設手機的今天（人在國外也對）。
  - 計算：一筆帳的台幣總數是付的人刷的加起來換算（`expenseParts()`），付的與分的兩邊都用 `allocate()` 照比例分：先取整數，剩下的零頭給小數最大的人，一樣大時照 id 順序，比例都一樣時就是以前的平分（一人多一元的規則不變），誰來算都一樣；付的人之一刪除帳號後只算還在的人付的，帳一樣平。`personTotals()` 算每個人付了、分攤與差額（扣掉還過的錢），`balancesOf()` 是它的差額。
  - 誰給誰：`minimalTransfers()` 每次讓欠最多的還給應收最多的，筆數最少，結算一律用台幣。已結清與記還款都寫一列 `travel_settlements`，復原就是刪掉；`settleTransfer()` 在交易裡重算一次，只收現在真的該給的那一筆，畫面太舊時回「帳有變動」；記還款（`recordRepayment()`，參考分帳龍寶寶的還款）是任意金額的台幣整數，給與收的人要是這趟的人或還留在帳上的人。
  - 畫面（使用者選的「由上到下四段」，`web/expense-view.ts` 的 `expenseBoard()`）：這趟總共與各類別（多的在前面）、每個人（付了、分攤、差額，點名字打開他的明細：付的、分到的與還款，參考分帳龍寶寶的帳目明細）、誰給誰（「複製結算」把旅程名稱、總共與誰給誰複製到 LINE，「記還款」，下面是還款紀錄可以復原）、每一筆照日期分組（新的日子在上面，出發前的併成一組，沒有日期的舊帳排最後，前面是類別圖示）。
  - 匯率手動填（使用者的決定，不接匯率 API），新增時預填這趟同一種貨幣最後用的（`lastRates()`）。
  - 成員離開後帳留著，名字由 `TripDetail.people` 讀（比 `members` 多了留在帳上的人），只有刪除帳號才跟著外鍵刪：那個人付的帳不見，他分的那一份由其他人重新平分，每一筆自己都是收支相抵，所以誰給誰永遠算得平。回程 7 天後跟旅程一起刪掉（寫在分帳的 i 圓圈）。
  - 畫面是第三個 `trv-fold`，平常收起來，標題列寫「你要付 $X」；其他成員靠行程更新通知知道（`announce()`）。
