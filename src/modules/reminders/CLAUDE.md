# 提醒與倒數（reminders）的注意事項

全站的規則（架構、慣例、安全、多人、快取、測試、資料保留、部署）在根目錄的 `CLAUDE.md`，這裡只寫這個部分自己的；文中的〈多人〉〈快取〉這類章節都在根目錄那份。

- 只有首頁卡片（`homeOnly`），資料表 `reminders_items`（每人多列）。規則都在 `lib/rules.ts` 的 `parseReminder()`：標題 NFC 正規化、連續空白縮成一個，1～30 字（用 code point 算，表單不設 `maxLength`：它算 UTF-16，emoji 打不滿）；日期是真實存在的日期、今天（台北）到 10 年後；通知是不通知或 `NOTIFY_DAYS`（當天、前 1／3／7／14／30 天），新增預設當天。
- 重複（使用者要的）：`repeat` 是不重複、每月或每年（`REMINDER_REPEATS`）。下一次的日期用 `nextOccurrence()` 算，今天也算，沒有那天就月底；`date` 留著第一次的日期，每次都從它算（31 號才不會變成 30 號），重複的項目不會被排程刪掉。
- 使用者要求不重複的日期過了就刪除：日期當天還在，隔天消失。`cachedReminders(userId)` 回這個人全部的項目，卡片在快取外面用今天的台北日期過濾（`web/reminders-view.ts`），不然過了午夜快取裡的舊資料會多顯示一天。過期還沒刪的項目修改時回「找不到」（畫面看不到，改回未來會繞過上限）。
- 每人最多 50 個還沒過期的（`ITEM_LIMIT`）：同一個交易裡先 `lockUserRow(tx, userId, "no key update")` 再數。收 id 的讀寫同時比對 `user_id`，別人的 id 回「找不到這個提醒，請重新整理頁面」。
- 排程 `reminders:daily`（`service/daily.ts`，台北 07:00 與 12:00 那個小時）：先寄再刪。擁有者沒停用、今天是當天或提前那天的項目逐筆 `sendOnce()`（scope `reminders:due`，key 是 `claimKey(項目 id, 今天)`），一筆出錯不擋其他筆，寄不出去的中午那一次再寄；同一天有好幾則時最急的最後寫入（通知新的在上面）；通知的 kind 是 `due`、連到首頁，標題是「今天：」「明天：」「還有 N 天：」加標題，內文只有日期。接著刪掉 `date < 今天` 的列，只刪擁有者沒停用的。摘要只有數字。中午 12 點多之後才新增、今天到期或今天是提前那天的，當天不補寄。
- 畫面：每一列左邊是倒數方塊（`reminder-list.tsx` 的 `CountdownTile`：大數字加「天後」，今天與明天直接寫字，今天是警示色、三天內是主色），最近的 5 個直接顯示，其他的收在 `disclosure`；修改與刪除在 ⋮。結果用提示視窗；第一次新增與刪除時打開視窗的按鈕或那一列會不見，修改時那一列可能在最近 5 個與收起來的清單之間搬動，焦點都交給首頁卡片的外框。
